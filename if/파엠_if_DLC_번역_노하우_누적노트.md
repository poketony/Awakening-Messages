# 파이어 엠블렘 if DLC 번역 노하우 누적 노트

> 이 문서는 고정 규칙집이 아니라 계속 갱신하는 실전 노하우 기록이다.
> 번역 전에 읽고, 사용자 피드백이나 정발판 관찰에서 새 경향을 얻을 때마다 즉시 추가한다.

---

# 0. 최상위 대원칙 ― 가장 중요

## “지원회화를 참고한다”의 정확한 뜻

지원회화를 필요한 정보 한 가지를 찾는 사전처럼 사용하면 안 된다.

잘못된 방식:
- 존댓말 문제가 생김 → 존댓말만 찾음
- 명사가 궁금함 → 그 명사만 찾음
- 호칭이 궁금함 → 호칭만 찾음

올바른 방식:

> **대응하는 정발판 지원회화를 통째로 읽고, 두 인물이 서로에게 사용하는 한국어 화법 전체를 통합적으로 파악한 뒤 DLC 번역에 반영한다.**

정발 지원회화는 단순 참고문헌이 아니라
**“이 두 인물이 한국어판에서 서로 대화할 때 사용하는 언어 모델”**이다.

반드시 함께 파악할 것:

1. 상호 존비어
   - A → B 존댓말/반말
   - B → A 존댓말/반말
   - 감정이 격해져도 유지되는지
   - 짧은 응답만 반말로 섞이는지

2. 상호 호칭
   - 아빠 / 아버지 / 아버님 / 엄마 / 어머니
   - 이름 직접 호명
   - `너` 또는 이름 생략
   - 상황별 호칭 변화

3. 문장 어미
   - `~요`, `~죠`, `~네요`, `~습니다`
   - `~구나`, `~거라`, `~해`, `~한다`
   - 해당 관계에서 반복되는 특징적 어미

4. 명사와 공식 용어
   - 물건, 기술, 직업, 종족, 음식, 장소
   - 캐릭터가 실제 정발판에서 특정 사물을 뭐라고 부르는지

5. 일반 어휘 선택
   - 모두 / 다들
   - 기쁘다 / 즐겁다
   - 돕다 / 힘이 되다
   - 말하다 / 얘기하다
   - 같은 뜻이어도 해당 캐릭터가 실제로 선호하는 표현

6. 말버릇과 감탄사
   - 당황, 놀람, 웃음, 머뭇거림
   - 말더듬기
   - 특유의 추임새

7. 대화 리듬
   - 짧고 건조한가
   - 장황한가
   - 능청스러운가
   - 어린가
   - 문어적인가

8. 감정 표현 방식
   - 애정을 직접 표현하는가
   - 돌려 말하는가
   - 화낼 때 말투가 어떻게 변하는가
   - 쑥스러울 때 문장이 어떻게 무너지는가

9. 관계 한정 말투
   - 평소 타인에게 쓰는 말투와 가족에게 쓰는 말투가 다른가
   - 부모·자식, 부부, 형제 관계에서만 나타나는 특징이 있는가

10. 본편 콜백
    - DLC에서 본편의 사건, 농담, 고백, 조언, 기술명, 노래 가사 등을 재언급하면 새로 번역하지 않고 정발판 표현을 우선 재사용한다.

### 작업 순서

> **정발 지원회화 전체 독해 → 관계별 한국어 화법 세팅 → DLC 일본어 원문 해석 → 번역**

다음 방식은 금지:

> DLC 번역 → 문제 생길 때마다 정발판에서 필요한 것만 검색

# 1. 일본어 DLC 원문과 정발 지원회화의 역할

## 일본어 DLC 원문
다음을 결정한다.
- 장면에서 실제로 무슨 말을 하는지
- 의미
- 감정
- 농담 구조
- 화행 기능
- 의도적인 말투 붕괴

## 한국 정발판 지원회화
다음을 결정한다.
- 이 캐릭터가 한국어로 어떻게 말하는지
- 상대와 어떤 존비어를 쓰는지
- 어떤 호칭을 쓰는지
- 어떤 어휘와 명사를 쓰는지
- 감탄사와 말버릇
- 공식 용어

핵심:
> **일본어가 내용, 정발판이 한국어 캐릭터성의 기준이다.**

---

# 2. 효율화 관련 실패와 교훈

과거 문제:
- 일부 부모회화만 확인하고 나머지에 패턴을 일반화
- “평소 존댓말 캐릭터”라는 이유로 부모→자식 존댓말을 유지
- 필요한 항목만 검색하고 지원회화 전체를 읽지 않음

결과:
- 칸나 부모회화 존댓말 오류
- 이미 끝난 범위를 다시 전수 검수
- 조사 제어코드 재작업
- 전체 부모 존댓말 표를 뒤늦게 작성

교훈:

> **몇 분 아끼려는 생략이 수십 배의 재작업을 만든다.**

앞으로 효율화는:
- 참조 파일을 빨리 찾기
- 검사를 자동화하기
- 미리 표를 만들기

에만 사용한다.

**참조 파일 자체를 읽는 과정을 생략하는 방향의 효율화는 금지.**

---

# 3. 모두 ↔ 다들

피드백 사례:
- `모두들 조심해!` → `다들 조심해!`는 적절했음.
- 그러나 그 피드백을 일반화해서
  `모두한테 짐이 되고 싶지 않아.` → `다들한테 짐이 되고 싶지 않아.`
  로 바꾼 것은 부적절했음.

교훈:
- `みんな = 다들` 같은 고정 치환 규칙 금지.
- 문맥, 화자의 태도, 문장의 진지함을 보고 판단.

예:
- 직접적 구호/호소: `다들 조심해!`
- 진지하고 포괄적인 진술: `모두에게 짐이 되고 싶지 않아.`

단, 이것도 고정 규칙이 아니다.
**앞으로 모두 ↔ 다들은 번역 감각과 문맥으로 판단한다.**

# 4. 사용자 지정 표기

## 운동명
- `팔굽혀펴기` ❌
- `팔 굽혀 펴기` ✅

## 미타마의 표현
- `하이쿠` ❌
- `시` ✅
- 필요하면 `시구`, `시적인 표현`

일본 문화 형식명을 과도하게 노출하기보다 정발판 한국어 감각을 따른다.

# 5. 조사 제어코드

정발판 분석:

- `$KrP1|` = `(은)는`
- `$KrP2|` = `(을)를`
- `$KrP3|` = `(이)가`
- `$KrP4|` = `(과)와`
- `$KrP5|` = `(으)`
- `$KrP6|` = `(이)`

가변 이름 `$Nu` 뒤:
- `$Nu가` ❌ → `$Nu$KrP3|`
- `$Nu를` ❌ → `$Nu$KrP2|`
- `$Nu는` ❌ → `$Nu$KrP1|`
- `$Nu와` ❌ → `$Nu$KrP4|`
- `$Nu로` → `$Nu$KrP5|로`
- `$Nu랑` → `$Nu$KrP6|랑`
- `$Nu야` → `$Nu$KrP6|야`
- `$Nu라고` → `$Nu$KrP6|라고`
- `$Nu라는` → `$Nu$KrP6|라는`

주의:
- `$Nu님이`
- `$Nu씨에게`
- `$Nu 오라버니는`

처럼 변수 뒤에 고정 호칭이 붙었다면 조사는 그 호칭을 기준으로 하므로 `$KrP`를 기계적으로 넣지 않는다.

교훈:
> 새 규칙을 사용자에게 전달받았으면 “알겠다”로 끝내지 말고 **그 즉시 최종 QA 항목에 편입한다.**

---

# 6. 부모·자식 존비어

가장 큰 실패:
- 부모 지원회화를 통합적으로 읽지 않고
- 평소 캐릭터 말투나 일부 사례를 기준으로 부모·자식 말투를 추정함.

교훈:
> **일본어 원문의 존댓말보다 정발판 같은 관계의 한국어 현지화가 우선한다.**

또한:
> **고정 부모의 경향을 가변 부모 관계에 일반화하지 않는다.**

별도 참조:
`파엠_if_2세대_고정부모_존댓말_전체표.md`

이 표는 빠른 색인일 뿐,
실제 번역 때는 대응 `*_親子.txt`를 다시 읽는다.

# 7. 존댓말은 단순 O/X가 아니다

예: 셀키
- 기본적으로 아빠에게 `~요`
- 그러나 짧은 응답에서 `응!`, `아니야` 같은 반말형이 섞임

따라서:
- 존댓말 캐릭터니까 모든 문장에 `요` 삽입 ❌
- `응`이 한 번 나왔으니 반말 관계로 판정 ❌

**문장 단위 + 대화 흐름으로 판단한다.**

---

# 8. 호칭도 별도로 확인한다

부모 호칭은 캐릭터성의 일부다.

예:
- 시로 → 료마: `아버지`
- 키라기 → 타쿠미: `아버지`
- 아스기 → 사이조: `아빠`
- 미타마 → 아자마: `아버님`
- 카도리 → 츠바키: `아빠`
- 라자트 → 하야토: `아빠`

존댓말만 맞아도 호칭이 틀리면 정발 캐릭터성이 무너진다.

---

# 9. 말더듬기

과거 오류:
말더듬기를 “완성된 첫 음절 반복”으로 오판.

잘못:
- `카, 칸나` → `칸, 칸나`
- `괘, 괜찮아` → `괜, 괜찮아`

올바른 예:
- `カ、カンナ` → `카, 칸나`
- 정말 → `저, 정말`
- 얼마 → `어, 얼마`
- 갑자기 → `가, 갑자기`
- 말 안 → `마, 말 안`
- 엄마 → `어, 엄마`
- 물론 → `무, 물론`
- 괜찮아 → `괘, 괜찮아`
- 별로 → `벼, 별로`
- 혹시 → `호, 혹시`
- 일단 → `이, 일단`

말더듬기는 철자 반복이 아니라
**실제 발화가 중간에서 끊기는 느낌**이다.

# 10. 일본어 감탄사 음차 금지

금지:
- はわわ → 하와와
- あわわ → 아와와
- ひゃあ → 햐아
- うわわわ → 우와와와

정발판 같은 캐릭터 표현과 한국어 감정 기능을 우선한다.

예:
- 펠리시아 `はわわ` → `으아아`, `흐아아`
- `あわわ` → `어어어…`, `으아아…`, `아, 아니…!`
- `ひゃあっ` → `꺅!` / `으악!`
- `わわっ` → `앗!`, `어엇!`
- `あたたた` → `아야야야!`

# 11. 대시

- `—` ❌
- `―` ✅

최종 검사에서 U+2014 EM DASH 0개 확인.

# 12. 전각 공백

일반 한국어 문장에서는 U+3000 금지.

예외:
`「첫째 줄
　둘째 줄」`
처럼 열린 인용문의 다음 표시 행 들여쓰기라는 명확한 서식 기능이 있을 때.

즉:
- 전각 공백 무조건 제거 ❌
- 일본어 원문에 있으니 무조건 유지 ❌

기능을 보고 판단.

# 13. 한국어 형태론

과거 오류:
- `조미료를 뒤집어쓰는다고!?` ❌
- `조미료를 뒤집어쓴다고!?` ✅

검사:
- `-ㄴ다고 / -는다고`
- `-냐고`
- 과거형
- 시제
- 받침 결합
- 조사
- 높임법

사용자가 특정 어절을 지적하면 해석론보다 먼저 형태소/활용 오류를 확인한다.

# 14. 정발판 자체 표기 존중

정발판 스타일이 명확하면 일반 맞춤법 취향으로 고치지 않는다.

예:
- `$Nu님`
- `료마님`
- `카밀라님`
- `제이콥씨`
- `하야토씨`

반면 실제 정발에:
- `$Nu 오라버니`

처럼 띄어쓰기가 있다면 그대로 유지.

즉 특정 사례를 또 무리하게 일반화하지 않는다.

# 15. 확인된 공식 용어

- `コウガ公国` → `코가 공국`
- `絡繰` → `꼭두각시`
- `漬物` → `야채 절임`
- `アウェイキング・ヴァンダー` → `어웨이킹 밴더`
- `ノスフェラトゥ` → `노스페라투`

시구레 노래:
- `ユラリ、ユルレリ…` → `하늘거리는 물거품…`
- `うたかた…おもい…めぐるはかり` → `정처없는 마음의 저울…`
- `つたう、みなすじ…そのてが…ひらく…あすは…`
  → `이어지는 물줄기… / 그 손이 개척하는 미래…`

공식 용어는 개인적 자연스러움을 이유로 새로 번역하지 않는다.

# 16. 사용자 직접 교정에서 얻은 번역 감각

## 어미는 태도를 담는다
`그렇게 당황하다니, 귀여운 아이.`
→ `그렇게 당황하다니, 귀여운 아이네.`

교훈:
종결 어미가 화자의 태도와 온도를 결정한다.

## 접속어의 구어성
`하지만 그 쑥스러워하는 얼굴도 귀엽구나.`
→ `근데 그 쑥스러워하는 얼굴도 귀엽구나.`

교훈:
일본어 접속사를 문어적으로 직대응하지 않는다.

## 조건의 강도
`혹시 모기가 날아오면`
→ `만약 모기가 날아오면`

교훈:
`혹시/만약`의 조건성 차이를 본다.

## 제안과 명령
`무슨 일 있으면 엄마한테 말해 봐?`
→ `무슨 일 있으면 엄마한테 말해 볼래?`

교훈:
문장의 화행 기능을 본다.

## 감정적 강조
`싸울 수가 없어!`
→ `싸울 수가 없다구!`

교훈:
정보보다 감정이 중요한 대사는 한국어 구어적 강조를 살린다.

## 인용문 말투
`활은 맞히는 게 아니라, 저절로 맞는 거야.`
→ `활은 맞히는 게 아니라, 저절로 맞는 것.`

교훈:
격언/인용문의 문체는 평상 대사와 다를 수 있다.

## 출처 표현
`아버지한테 배운 거예요?`
→ `아버지한테서 들은 말인가요?`

교훈:
원문의 의미 관계를 정확히 잡는다.

## 의성어
`활로 쾅~ 하고요!`
→ `활로 슉~ 하죠!`

교훈:
일본어 음가가 아니라 실제 행동 이미지에 맞는 한국어 의성어를 쓴다.

## 양태
`사용인보다 군인이 천 배는 낫다`
→ `사용인보다 군인이 천 배는 낫겠다`

교훈:
사실 판단 / 추정 / 의향을 구분한다.

## 담화 관계
`하지만 미안해요.`
→ `그래도 미안해요.`

교훈:
접속사는 앞문장과의 논리 관계까지 본다.

---

# 17. “자연스럽게”의 정의

자연화한다고 다음을 하면 안 된다.
- 원문의 태도 약화
- 캐릭터 말투 평준화
- 모든 문장을 현대 일상어로 변환
- `모두`를 전부 `다들`로 변환
- 독특한 문체를 무조건 제거

여기서 자연스러움은:

> **정발판의 그 캐릭터가 그 상대에게 실제 그 장면을 말한다면 자연스러운가**

를 뜻한다.

---

# 18. 검수는 재창작이 아니다

QA는 sparse하게 한다.

수정 우선순위:
- 의미 오류
- 정발판 불일치
- 존비어/호칭 오류
- 공식 명사 오류
- 한국어 문법 오류
- 형식/제어코드 오류
- 심한 부자연스러움

“다른 표현도 가능하다”는 이유만으로 멀쩡한 문장을 취향대로 대량 재작성하지 않는다.

---

# 19. 형식/제어코드

보존:
- MID
- `$Ws`
- `$Wm`
- `$Wa`
- `$Svp`
- `$E`
- `$k`
- `$p`
- literal `\n`
- `$t`
- `$w`
- `$Wd`
- `$a`
- 기타 엔진 제어코드

코드 내부 일본어 식별자는 번역하지 않는다.

최종 기계검사:
- MID 개수/순서
- `$k`
- `$p`
- `\n`
- `$Ws`
- `$Wm`
- `$Svp`
- 제어코드 순서
- 일본어 가시문자 잔존
- `—`
- U+3000
- `�`
- `$Nu` 생짜 가변 조사

# 20. FEFTS/폭 검사

실제로 FEFTS 또는 렌더링 폭 검사를 하지 않았다면
“폭 검사 완료”, “240px 문제 없음”이라고 말하지 않는다.

실제 수행한 검사와 추정 판단을 구분한다.

# 21. 노하우 노트 업데이트 프로토콜

## 작업 전
1. 통합 작업 지침 읽기
2. 이 노하우 노트 읽기
3. 해당 관계의 정발 지원회화 전체 읽기
4. 공식 용어 검색

## 작업 중
새 경향 발견 즉시 메모:
- 말투
- 호칭
- 어휘
- 명사
- 감탄사
- 현지화 방식
- 본편 콜백
- 제어코드 사용

## 사용자 피드백이 생기면 반드시 기록
1. 잘못된 번역
2. 사용자가 고친 번역
3. 왜 후자가 더 적절한지
4. 어디까지 일반화 가능한지
5. **어디서부터 일반화하면 안 되는지**

## 작업 후
- 같은 실수를 막는 QA 항목 추가
- 단일 사례를 보편 규칙으로 과잉 일반화하지 않았는지 검토

---

# 22. 실패 사례를 기록하는 이유

실패 기록은 같은 오류가 다른 캐릭터/다른 DLC에서 형태만 바뀌어 재발하는 것을 막기 위한 것이다.

반복 위험 유형:
- 특정 피드백 과잉 일반화
- 지원회화의 한 요소만 검색
- 캐릭터 일반 말투를 가족 관계에 적용
- 공식 용어를 기억에 의존
- 새 제어코드 규칙을 다음 산출물 QA에서 누락
- 자연화 과정에서 태도/양태 손실

---

# 23. 가장 중요한 자기 점검 질문

번역문 한 줄을 확정하기 전에:

> **“나는 지금 이 문장을 일본어만 보고 번역하는가, 아니면 정발판에서 이 두 사람이 실제로 어떻게 말하는지를 이해한 상태에서 번역하는가?”**

후자라고 확실히 답할 수 없으면 지원회화를 더 읽는다.
